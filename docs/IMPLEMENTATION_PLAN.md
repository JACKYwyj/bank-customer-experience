# 实施计划与成本核算

## 一、实施阶段

### 第一阶段：设备盘点与模型评估

**目标**：确认输入质量及工作量

**具体任务**：
- [ ] 统一会话、流程和业务事项标识
- [ ] 接入排队与操作日志
- [ ] 评估现有摄像头、终端和内网资源复用条件
- [ ] 完成接口梳理
- [ ] 离线模型评估

**交付物**：
- 设备盘点报告
- 接口梳理文档
- 离线评估报告

### 第二阶段：业务接入与验证

**目标**：验证响应是否及时、问题能否解决

**具体任务**：
- [ ] 连接识别、话术和流程接口
- [ ] 将建议转换为人员待办
- [ ] 设置超时升级路径
- [ ] 在少量业务上接入解释、求助与人工派单

**交付物**：
- 业务接入方案
- 验证测试报告

### 第三阶段：现场试用

**目标**：开展有限现场试用

**具体任务**：
- [ ] 接入真实模型
- [ ] 完成离线评估后开展有限现场试用
- [ ] 收集一线人员反馈
- [ ] 调整告警阈值和话术规则

**交付物**：
- 现场试用报告
- 规则调优方案

### 第四阶段：业务闭环

**目标**：形成完整的业务闭环

**具体任务**：
- [ ] 将服务状态持久化回写
- [ ] 处理结果和客户评价记录
- [ ] 部署数据持久化方案
- [ ] 异常重试和运行监测机制

**交付物**：
- 完整业务闭环方案
- 数据持久化设计

## 二、成本测算

### 2.1 测算范围与基本假设

为判断试点投入，将以**五个网点共用一套平台、每个网点部署一套系统**的方案进行预算示例。

**基本假设**：
- 摄像头、终端和内网等现有资源具有复用可能
- 试点前逐点核对设备性能、接口条件、网络与数据合规要求
- 端侧优先评估开源模型，根据试点数据进行必要的模型适配

> **注意**：以下为假设性预算测算，具体金额以设备盘点和人员工时核算为准。

### 2.2 建设投入

| 建设项目 | 假设与计算方式 | 新增现金支出 | 说明 |
|----------|----------------|--------------|------|
| 服务器硬件 | 存量资产 | 待盘点确认 | 仅在满足性能、接口和合规要求时复用 |
| 内网复用 | 存量资产 | 待盘点确认 | 同上 |
| 系统开发 | 新增开发 | 待核算 | 含定制化开发 |
| 接口联调 | 新增工作 | 待核算 | 与银行业务系统联调 |

### 2.3 年度运维投入

| 运维项目 | 假设与计算方式 | 新增现金支出 | 说明 |
|----------|----------------|--------------|------|
| 系统运维、bug修复、小版本迭代 | 内部运维固定编制 | 0（内部投入）| 预计占用20人日，需计入机会成本 |
| 模型迭代优化 | 内部算法固定编制 | 0（内部投入）| 预计占用15人日，需计入机会成本 |
| 网点现场巡检维护 | 内部运维固定编制 | 0（内部投入）| 预计占用30人日，需计入机会成本 |

### 2.4 成本汇总

| 类别 | 金额 | 说明 |
|------|------|------|
| 新增成本小计 | 待核算 | - |
| 内部投入 | 65人日 | 不等于没有成本 |
| 机会成本 | 待折算 | 按职责拆分计算 |

> **重要**：表中"0（内部投入）"仅表示暂不发生新增现金支出，不代表没有成本。公共研发、本地实施与运维工时需按职责拆分并折算机会成本，避免重计。

## 三、效益评估

### 3.1 评估指标体系

| 类别 | 指标 | 评估方法 |
|------|------|----------|
| **服务效率** | 首次响应时长 | 试点-对照设计 |
| | 重复询问次数 | 试点-对照设计 |
| **业务完成** | 自助办理完成率 | 试点-对照设计 |
| | 问题解决率 | 试点-对照设计 |
| **客户体验** | 客户满意度 | 问卷调查 |
| | 持续使用意愿 | 问卷调查 |
| **运营成本** | 投诉升级率 | 数据统计 |
| | 人工工作量 | 工时记录 |
| | 系统误报率 | 数据统计 |
| | 系统漏报率 | 数据统计 |
| | 内部机会成本 | 财务核算 |

### 3.2 评估方法

采用**试点-对照**设计：
```
效果 = (试点网点试运行前后变化) - (对照网点同期变化)
```

**评估原则**：
- 报告区间估计
- 满意度变化以分值或百分点分别表述，不混用相对增幅
- 情绪识别输出只用于辅助过程分析
- 客户是否满意、投诉是否解决，应以客户反馈和业务结果为准

### 3.3 采用决策标准

**扩大试点条件**：
- ✅ 服务指标改善
- ✅ 员工新增负担可控
- ✅ 成本可接受
- ✅ 客诉处理成本显著下降

## 四、分阶段决策

### 第一阶段末决策点

**完成内容**：
- 设备盘点
- 接口梳理
- 离线模型评估

**决策问题**：输入质量及工作量是否满足要求？

### 第二阶段末决策点

**完成内容**：
- 少量业务接入
- 响应及时性验证
- 问题解决率验证

**决策问题**：
- 响应是否及时？
- 问题能否解决？
- 是否进入第三阶段？

### 第三阶段末决策点

**完成内容**：
- 有限现场试用
- 预先约定的试点口径核算
- 成本与成效评估

**决策问题**：
- 业务改善要求是否达到？
- 新增工作量是否可控？
- 是否扩展多模态采集和更多网点？

### 推广决策

**注意事项**：
- 扩大覆盖可降低公共开发分摊
- 但网点数量增加可能带来模型维护、接口差异和平台资源费用上升
- 不能直接假设单位成本线性下降

**决策应报告**：
- 一次性投入
- 年度费用
- 真实服务改善
- 可兑现收益
- 继续/调整/停止的判断依据

| 隐私风险 | 数据合规要求 | 高 | 联邦学习、差分隐私 |
| 业务风险 | 规则不合理 | 中 | 试点数据验证规则 |
